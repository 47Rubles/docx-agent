## Не реализовано и требует проектирования
- RAG, отдельный синтезатор, State Machine и ревизионный diff с действительными `<w:ins>` / `<w:del>`.
- Поддержка `.dotx`, бот-интерфейс, строгая валидация ECMA-376, производительный benchmark.
- Полный MathML→OMML XSLT и расширенное восстановление невалидных LLM-разделов.

## Замечания к ТЗ
- `PROJECT_SPEC.md` в одном месте допускает четыре уровня заголовков, тогда как `AGENTS.md` ограничивает тремя. Реализация придерживается более строгого ограничения 1..3.
- В примере PROJECT_SPEC.md API `latex2mathml.commands.process_latex()` не является надежным публичным API; текущий конвертер использует `latex2mathml.converter.convert()`.
- `w:sz=24` означает 3 pt, поскольку единица измерения равна 1/8 pt.
- `updateFields` запрашивает обновление Word, но не гарантирует мгновенное перестроение оглавления без подтверждения пользователя.

## Исправление ошибки теста на Windows (2026-10-22)

- Причина: конвертер `latex2mathml` в некоторых версиях не сообщает об ошибке для неизвестной команды `\\unknownCommand`; сборщик поэтому не выводил ожидаемый текст `[Формула не преобразована]`.
- Исправление: до конвертации проводится ограниченная проверка LaTeX-команд (`_validate_commands`); неподдерживаемые команды вызывают `FormulaConversionError`, которую компилятор перехватывает и заменяет формулу текстовым предупреждением.
- Добавлен регрессионный тест `tests/test_extensions.py` с исходным примером ошибки; локальный результат: 8 passed.
- Ограничение: список поддерживаемых команд пока не исчерпывающий, поэтому редкие допустимые макросы также будут помечаться как неподдерживаемые. Для полноценной поддержки произвольного LaTeX потребуется улучшенный парсер и полный MathML->OMML XSLT.
