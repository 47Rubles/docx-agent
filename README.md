# DocxGen Agent

Автономный агент генерации и версионирования документов DOCX.

Система преобразует неструктурированные текстовые требования (технические задания, регламенты, концепции) в валидные, профессионально свёрстанные документы Microsoft Word.

## Принцип разделения

Прямая генерация бинарного `.docx` языковой моделью исключена. Работа разделена на два контура:

1. **Когнитивный контур** — декомпозиция требований, устранение неопределённостей через диалог, синтез контента в абстрактное синтаксическое дерево (Document AST) со строгой валидацией Pydantic v2.
2. **Детерминированный компилятор** — трансляция AST в OpenXML через `python-docx` + прямой инжект XML через `lxml`, с контролем типографики, стилей и структуры файла.

## Архитектура

```text
Пользовательский ввод (свободный текст ТЗ)
        │
        ▼
┌───────────────────────────────────────────────────────────┐
│  Когнитивный контур (LLM pipeline)                        │
│                                                           │
│  1. Агент-Интервьюер  ◄── диалог ──►  Пользователь        │
│  2. Векторный контекст / RAG                              │
│  3. Агент-Архитектор (дерево разделов)                    │
│  4. Агенты-Синтезаторы (параллельная генерация глав)     │
└───────────────────────────────────────────────────────────┘
        │
        ▼
   [DOCUMENT JSON AST]  ← валидация схемы
        │
        ▼
  LaTeX ──► MathML ──► OMML (XSLT)
        │
        ▼
┌───────────────────────────────────────────────────────────┐
│  Компилятор DOCX (OpenXML)                               │
│  • Корпоративный шаблон (.dotx / .docx)                  │
│  • Табличный процессор / врезки / TOC / колонтитулы      │

        │
        ▼

```

## Ключевые инженерные решения

- **Формулы** — LaTeX → MathML → OMML через `MML2OMML.XSL`, встроенные векторные формулы Word вместо картинок.
- **Стили** — код не задаёт шрифты, кегль и отступы напрямую; сборщик опирается только на семантические стили шаблона.
- **Таблицы** — повтор шапки на переносе, защита строк от разрыва, ширины в `dxa`, объединение ячеек через `gridSpan` / `vMerge`.
- **Врезки** — одноячеечные таблицы с акцентной левой границей и пастельной подложкой.
- **Оглавление** — динамическое поле Word `TOC \o "1-3" \h \z \u` + `updateFields` для автопересчёта страниц при открытии.
- **Правки** — режим рецензирования: вставки в `<w:ins>`, удаления в `<w:del>` с сохранением автора и таймстемпа.
- **Изоляция сбоев** — ошибка в одном блоке (например, в LaTeX-формуле) не роняет сборку: блок заменяется текстовым эквивалентом с маркером предупреждения.

## Секреты и конфигурация

Ключ API **не хранится в репозитории**. В `config/settings.yaml` лежит только
плейсхолдер, который подставляется из переменной окружения в памяти:

```yaml
llm:
  api_key: "${LLM_API_KEY}"
```

| Среда | Где живёт ключ | Кто ставит |
|-------|----------------|------------|
| Локально | переменная уровня User `LLM_API_KEY` | `scripts/set-api-key.ps1` |
| Локально (альтернатива) | `.env` (в `.gitignore`) | вручную по `.env.example` |
| CI | GitHub Actions Secret `LLM_API_KEY` | Settings репозитория → Secrets |

Один и тот же секрет работает в обоих местах — код к нему обращается одинаково.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\set-api-key.ps1   # задать ключ
python scripts\smoke_test.py                                       # проверить связь
python scripts\check_secrets.py                                    # проверить репозиторий
```

Подробности, включая разбор «ключ утёк» и особенность заголовка
`x-goog-api-key` у Google, — в [`docs/SECRETS.md`](docs/SECRETS.md).
